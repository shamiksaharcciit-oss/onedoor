## 0. Read this first — do not rebuild

**The digests in §3 are of the exact files in `dist/` right now. Upload those. Do not run
`python -m build` again before uploading.**

The build is **not byte-reproducible** — measured during `0.6.0`: two builds of the same
tree differ, the wheel keeping its size and changing its hash. So a digest taken after
publication proves nothing about what was verified. *A digest answers exactly one
question, and this one answers "are these the bytes we verified", never "would building
again produce them."*

## 1. What this fixes — your five findings

| | Finding | Status |
|---|---|---|
| **F-A** | Studio `GET /` → Internal Server Error, every time | **Fixed** |
| **F-B** | decimal strings in `params` refused while `cost_eur` accepts them | **Escalated, not fixed** — it changes a verdict |
| **F-C** | no `onedoor.__version__` | **Fixed** |
| **F-D** | Studio app self-describes as `0.4.x` | **Fixed** |
| **F-E** | no PyPI-reader quickstart | **Fixed** |

**F-A**: the Studio's stores were opened once at startup while every route is a sync `def`
that FastAPI runs in a threadpool — a different thread per request, which `sqlite3`
refuses. Fixed with the pair `onedoor.service` has always used: `check_same_thread=False`
**and** a lock on every route. The regression test was written first and reproduced your
error verbatim before the fix existed.

**F-B is deliberately not in this release.** Measuring it found something sharper than the
report: `caps.resolve_cost` accepts decimal strings and `bounds` does not, so **adding a
`numeric` bound changes which wire types an action accepts**. The fix changes a verdict
from denied to permitted, which is wire-observable and therefore core's call, not mine.
See `escalations/ESCALATION-20260827-006.md`. The failing direction is closed — a denial,
never a permit — and *Known limitations* now names it.
