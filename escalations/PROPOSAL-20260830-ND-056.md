## 1. Contradictions between the directive and the code as it is

Reported first, per the standing rule. Six, in descending order of consequence.

### C1 — Approval-by-API already exists, is shipped, and is on PyPI

Forward 006 §2 (T2) rules: *"**No approval-by-API pre-Q7**: ratification remains the
human ceremony until actor identity (key_id) exists, because an approval without a
named approver is testimony."*

The Studio already serves one:

```
onedoor/studio/server.py:824    @app.post("/draft/{draft_id}/ratify")
onedoor/studio/server.py:825    def ratify_endpoint(draft_id: str, session: str) -> dict[str, Any]:
```

It takes `session` as a query parameter, calls `ratify_draft`, and returns
`outcome.receipt.sealed()` as JSON. It has been in the tree since `ND-052`/S3-T2 and it
is in the `0.6.2` wheel core downloaded from PyPI and smoke-tested.

Three further facts, each checked:

- It is **not documented**. The README's Studio section (lines 118–137) covers the bind
  refusal and the two store paths and nothing else; no `.md` file in the repository
  mentions this route.
- **No test posts to it.** `grep` over `tests/` finds `/drafts/{id}/ratify` (the HTML
  ceremony, `test_server_served.py:457–543`) and `/draft/{id}/repin`
  (`test_server_served.py:86`) — never `/draft/{id}/ratify`.
- It is not identity-free by accident. Migration `0017` stores `ratified_by_session`,
  *"declared, never authenticated — the longer name carries its own caveat."* The
  endpoint is honestly labelled. It is still approval by API.

**Why the V8 universal pass did not catch it.** It should not have. The pass enumerated
routes off the running app and applied six laws; none of the six asks *"does any route
perform the ceremony without the ceremony?"* R064 §2's law — *an app's surface is what
the server serves, not what the project remembers writing* — is what surfaced the route
table. What was missing was a law about what the routes are permitted to **do**. That is
a gap in the law set, not in the pass, and I would rather say so than claim a miss.

**The bind.** Removing the route is a breaking change to a published surface, which the
freeze bars until Sept 12. So the directive's wall cannot be built by *not* building
something; it can only be built by removing something, and removal is exactly what is
forbidden this week.

**Options, with my recommendation.**

1. **(Recommended) Leave it for `0.6.3`; add no new approval route; document the
   existing one truthfully**, in one sentence that says what it is — approval by API,
   with a declared, unauthenticated session string, predating the actor-identity work —
   and spec its retirement into the `0.7.0` line beside Q7's `key_id`, which is where
   actor identity lands anyway. T2 then genuinely adds no approval-by-API.
2. Remove it in `0.6.3` as a ruled exception to the freeze. Honest, and it makes the
   directive's sentence true, but it is a breaking change in launch week for a benefit
   that is a week away regardless.
3. Neuter it additively behind an opt-in flag. This is breaking for anyone calling it
   and buys nothing option 1 does not.

I will not choose between these. Option 1 is what I would do.

### C3 — "the FULL loader rulebook" cannot be delivered as worded without building the one thing the house forbids

`onedoor/studio/validate.py` is explicit that it is *"a wrapper over that function,
never a second validator"*, and its honesty clause states, in the module's own words,
that it reports **problems found, never all problems**, for two structural reasons:
`validate_policy` stops at the first failure *per rule*, and set-level defects are
invisible to a per-rule loop.

Both are still true of the engine today (`onedoor/guardrail/policy_loader.py:31–103`).
So "surfacing the FULL loader rulebook" and "nothing the loader would refuse at boot is
first discovered at boot" are reachable **as absolutes** only by changing
`validate_policy` from raise-on-first to collect-all. That changes fail-closed boot
semantics in the enforcer, and I will not do it on my own authority.

**What is achievable, additively, and is a real improvement.** The Studio today reaches
only the *last* stage of the loader's boot path, because the editor hands it
already-constructed `Policy` objects. The boot path is four stages:

| Stage | Function | Reachable in the Studio today |
|---|---|---|
| 1 | `_safe_load_decimal` — YAML syntax, non-mapping file, non-finite number | **no** |
| 2 | `Policy.model_validate` — schema errors | **no** |
| 3 | `EffectPolicy` / `Tier(int(...))` / `Caps.model_validate` | **no** |
| 4 | `validate_policy` — the per-rule rules | yes |

Upload changes this: an uploaded file enters at stage 1, so stages 1–3 become reachable
and must be surfaced. That is most of the directive's intent, and it is entirely
additive.

**Proposed honest wording**, replacing "the full rulebook":

> Every refusal the loader can produce for this candidate, at the stage that produces
> it — first failure per rule, and set-level defects still invisible.

The `INCOMPLETE_NOTICE` constant stays and renders beside every list, including an empty
one, exactly as it does now.

### C4 — two of the five named checks are not loader refusals at all

Forward 006 §2 (T1) names five things to surface. Checked against the code that decides,
not the names that suggest (R058 §4):

| Named | Verdict |
|---|---|
| schema errors | **correct** — `Policy.model_validate`, reachable via upload/raw pane |
| tier-1/2 without `compensating_command` | **correct and exact** — `policy_loader.py:33–42`; `Tier.AUTO = 1`, `Tier.AUTO_CAPPED = 2` (`models.py:47–48`) |
| `cost_param` absent from `bounds.required` | **correct and exact** — `policy_loader.py:43–49` |
| euro caps without `cost_param` | **not a loader refusal** |
| `strict_params` violations | **not an authoring-time property at all** |

*Euro cap without `cost_param`*: such a policy loads at boot without complaint. The
engine denies at **decision** time — `caps.py:313–325`, `CheckId.COST_UNKNOWN`, reason
*"no cost_param declared and the request carries no cost_eur"*. Presenting it as a boot
refusal would state a falsehood about the engine and would be the Studio inventing a
rule, which is the exact thing `validate.py` exists not to do.

*`strict_params`*: it is a runtime bounds check (`models.py:181`, default `True`;
`bounds.py:27–31` rejects an unknown param **in a request**). A policy cannot violate
it; a request can. There is nothing here for an editor to refuse.

**Proposal: build all five, in two separately-typed lists that are never merged.**

- **"The loader will refuse this at boot"** — stages 1–4 above. Refusals.
- **"This rule will behave like this at decision time"** — the euro-cap-without-
  `cost_param` case (a cap that denies every request), `strict_params` (which params
  this rule will reject), and the existing `coverage.DECLARED_INERT` detector.

Both are worth showing; a euro cap that silently denies everything is precisely what an
author wants to know. Merging them would make the Studio claim a boot refusal the loader
does not perform. This is R058 §6's two-voice separation applied to validation.

One note on `DECLARED_INERT`: `ND-053` will make an inert effect label a boot refusal,
post-Sept-12. Today it is not one. The advisory therefore describes **today**, pinned by
a forbidden-word test in the R063 §3 pattern.

## 2. T1 — editor, upload, dynamic validation

**Additive. Ships first. Nothing here writes to the enforcer store.**

### 2.1 Upload

`POST /drafts/upload` creates a draft from an uploaded YAML file and lands on that
draft's editor. Same parser path as every other write: the bytes go straight into stage
1 of §1-C3's table.

**One dependency decision that reverses a recorded one, flagged rather than slipped in.**
`server.py:381` deliberately avoids `python-multipart`, reasoning that *"a dependency for
one text field is one the `[studio]` extra does not need."* A file input forces
`multipart/form-data`; there is no urlencoded route to it. The options are (a) add
`python-multipart>=0.0.9` to the `[studio]` extra, or (b) hand-parse multipart, which is
a second implementation of a parser and is not on the table here. I propose (a), and I
am recording it as a reversal with its reason — a **file** field is a different case
from a text field — rather than letting the earlier comment quietly become wrong.
**Q10** if core would rather rule on it.

The uploaded bytes are frozen verbatim via `descriptions.freeze` (E10: a `BLOB`, no
decode round trip), so the draft can always cite what was actually uploaded.

### 2.2 Staged validation

New `validate.candidate_from_yaml(text) -> StagedProblems`, running the loader's **own**
functions in the loader's own order, stopping at the stage that fails because later
stages cannot run on what earlier stages could not build:

1. `policy_loader._safe_load_decimal` → syntax, non-mapping, non-finite number
2. `policy_loader._policy_from_entry` per entry → pydantic errors, with `loc` paths
3. effect construction → `Tier(int(...))`, `Caps.model_validate`
4. existing `validate.problems` → the per-rule rules

**Positions** come from `yaml.compose()` node start marks — the loader's own parser
reporting where it read a thing, not a second scan of the text — joined to pydantic's
`loc` path. A position that cannot be resolved renders as *"position not resolved"*, not
as line 1: three outcomes, and a wrong line number in an error message is worse than
none.

**The second list** (decision-time behaviour, §1-C4) is computed beside it and rendered
in its own region under its own heading, with `INCOMPLETE_NOTICE` on the refusal list
and its own limit sentence on the behaviour list.

### 2.3 Live, without a second parser in the browser

R063 §1 is load-bearing: the panes sync through the server *because the server owns the
only parser*, and *"they can't drift because there's nothing to drift between."* Live
validation must not weaken that.

- `POST /drafts/{id}/validate` returns an **HTML fragment** — the two lists, server-
  rendered from a server-side parse.
- A small inline debounced `fetch` posts the pane's text and swaps the fragment in. **It
  parses nothing.** A structural test asserts the Studio's JS contains no YAML handling
  and no policy vocabulary.
- With scripting off, the existing V7 round trip is the fallback and the page is exactly
  what it is today. Progressive enhancement, the shell's established shape.
- The fragment is a served page for law-test purposes: seal, external-origin and
  honesty-footnote laws all apply to it.

## 3. T2 — policy REST API

**Additive. Loopback only, on the same app — `require_loopback` binds it for free.**

Routes under `/api/v1/`, all typed refusals, all through the one parser:

| Method | Path | Purpose |
|---|---|---|
| `POST` | `/api/v1/drafts` | create (JSON, or from a YAML body) |
| `GET` | `/api/v1/drafts` · `/api/v1/drafts/{id}` | list / read, including base-version pin state |
| `PUT` | `/api/v1/drafts/{id}/rules/{action_type}` | add or update one rule in a draft |
| `DELETE` | `/api/v1/drafts/{id}/rules/{action_type}` · `/api/v1/drafts/{id}` | remove |
| `GET` | `/api/v1/drafts/{id}/validation` | both lists from §2.2, as data |
| `POST` | `/api/v1/drafts/{id}/submit` | **submit for ratification — marks ready, ratifies nothing** |
| `GET` | `/api/v1/policies` · `/api/v1/policies/{action_type}` · `/api/v1/versions` | queries, read from the pinned snapshot (R058 §1) |

**`submit` is not approval.** It sets a draft's state to `submitted` and returns the URL
of the ceremony page. The human ceremony remains the only path to the enforcer store.
The API docs carry the directive's one sentence — subject to C1's resolution, since as
things stand that sentence would be false while `POST /draft/{id}/ratify` serves.

**Refusal typing.** Every route answers with the whole response honest — status, media
type and body together (R059 §2). `404` unknown draft; `409` a well-formed request the
world declines (stale pin, already submitted); `422` a candidate the parser refused,
carrying the staged problems; `400` malformed request. Absent, unverifiable and failed
stay apart.

**One thing to rule on (Q12).** V8 set `openapi_url=None` because `/openapi.json`
*"published an API surface nobody chose to publish."* T2 is a surface someone chooses to
publish. I propose re-enabling **`openapi_url` only**, at `/api/v1/openapi.json`, and
leaving `/docs` and `/redoc` off — they are what pulled Swagger, ReDoc, fonts and a
favicon from CDNs and made the header's promise false. JSON fetches nothing, so the
no-external-origin law is untouched. Core turned this off on a finding; I will not turn
it back on without a ruling.

## 4. T3 — natural-language authoring

**The substrate already exists.** `onedoor/studio/proposer.py` ships the `Proposer`
protocol, `DerivationRecord` (`onedoor/derivation-record/1`), the non-empty-instrument
rule, `Mention`, `FixtureProposer`, and the two face sentences `NOT_REDERIVABLE` and
`AUTHORITY_FROM_CHECKS`. `descriptions.py` freezes operator bytes verbatim and owns the
append-only `derivation_records` table with its no-update/no-delete triggers. T3 is
**wiring, a screen, and a live client** — not a new architecture.

The seam is already cut and already refuses:

```
onedoor/studio/proposer.py:  def live_proposer(...) -> Proposer:
    raise ProposerUnavailable("no live proposer is configured. ...")
```

### The six walls, and where each is enforced

1. **Declared instrument, pinned, recorded on the draft.** `HttpProposer.identity()`
   returns `{kind, endpoint_host, model, prompt_digest, pack_digest}` — non-empty is
   already enforced by `derive`, which raises on an empty block. `proposer_provenance`
   is `live`, and it rides **inside** the record's digest, so a fixture-drafted
   candidate cannot be relabelled as a model's work without breaking the record's own
   address. The draft gains `derivation_record_digest` (§6).
2. **Same single parser.** Generated YAML goes through `validate.candidate_from_yaml` —
   the identical T1 path. A refused generation renders as refused, with the staged
   reasons, and **is never auto-repaired**: a structural test asserts no retry, rewrite
   or fixup path exists between the model client and the parser.
3. **The ceremony renders what the parser read.** The approval surface renders the
   parsed rules through the same guided-pane renderer as a hand-written draft. The
   model's own prose, if shown, sits in its own region labelled as the model's summary,
   in the R058 §6 two-voice shape — quoted, attributed, visually distinct, with the
   page stating that nothing above it derives from it.
4. **BYO endpoint, opt-in, off by default.** Configured by explicit flags/env; no
   bundled credentials, no default provider. **Absent configuration means the tab is
   absent** — `shell.TABS` already carries a `built` flag that governs whether a tab
   renders, so absence is the existing mechanism, not a new one. Nothing falls back to
   the fixture: `live_proposer`'s docstring already names that as the worst outcome.
   Transport is stdlib `urllib.request` — **no new dependency**; `httpx` is in `[dev]`
   only and the `[studio]` extra should not grow a client for one POST.
5. **Capability language exact.** `"drafts proposed by a model, ratified by you"` as a
   single constant, rendered everywhere, with a forbidden-word test in the R063 §3
   pattern refusing `AI writes`, `automatically`, `generates your policy` and
   `writes your policies` across every T3 surface.
6. **The dark-surface list** (constitution principle 4, §1-C5). Every proposal ends with
   what the description mentioned that got no rule, and why — `Mention` rows with
   `covered_by is None`, quoting the description's own words, never a paraphrase.

**Isolation stays.** `tests/studio/test_proposer_isolation.py` already asserts that
nothing the engine consults while deciding may import this module or reach a network
client. The live client extends the surface that test guards; the test is strengthened
to cover it rather than left pointing at the fixture.

## 5. Tests-first plan

House standard: the test lands before or with the code, and any claim of impossibility
is written as a test — *a claim of impossibility is a test, or it is a boast* (R063 §1).
Sabotage pairs where a checker is involved, per Forward 005: a checker that has never
been shown a lie has never been shown to look.

**T1**

- `test_staged_validation.py` — one case per stage, each proving the stage is reached
  **and** that later stages did not run; a YAML syntax error must not report as a schema
  error. Three outcomes on positions: resolved, unresolved, absent.
- `test_upload.py` — upload creates a draft; the frozen bytes round-trip byte-for-byte
  (E10, including a file with CRLF and a BOM, which must survive unmodified); a refused
  file creates a draft that renders its refusals rather than 500-ing.
- `test_two_lists_never_merge.py` — **the C4 fence.** A candidate with a euro cap and no
  `cost_param` must appear in the behaviour list and must be **absent** from the refusal
  list; sabotaged by asserting the fixture really does load cleanly through
  `policy_loader.load_file`, so the test cannot pass on a candidate that was refused for
  some other reason.
- `test_no_parser_in_the_browser.py` — structural, over the served JS: no YAML
  vocabulary, no policy field names, no branching on rule content.
- Law tests already universal (seal, external origin, honesty footnote, digest format,
  empty state, disabled controls) extended to the new fragment route by adding it to the
  route table the universal pass reads off the running app.

**T2**

- `test_api_refusals.py` — parametrised over every route × every refusal class, asserting
  status **and** media type **and** body together (R059 §2).
- `test_submit_is_not_approval.py` — the wall as an assertion: after `POST /submit`, the
  enforcer's `policy_current` is unchanged, no ratification row exists, and the version
  pointer has not moved. Sabotaged by proving the ceremony *would* have moved them.
- `test_one_parser.py` — structural: every write route reaches
  `validate.candidate_from_yaml`; no route constructs a `Policy` by hand.
- `test_api_reads_the_snapshot.py` — R058 §1: the query routes read the snapshot the
  header names, sabotaged by writing a divergent row into live `policies` and asserting
  the answer does not move.

**T3**

- `test_walls.py` — one test per wall, each in the failing direction first.
- `test_no_auto_repair.py` — a model response the parser refuses must surface refused;
  structural assertion that no retry/rewrite path exists.
- `test_absent_not_broken.py` — with no configuration, the tab is absent from `TABS`,
  the route 404s, and **no page mentions the feature**. Sabotaged by configuring it and
  asserting all three flip.
- `test_capability_language.py` — the forbidden-word list over every T3 surface, plus
  the exact-constant assertion, checked escaped **and** unescaped (R061 §3).
- `test_dark_surface.py` — a description mentioning something with no rule produces a
  `Mention` with `covered_by is None` and renders it; silence about a mention fails.
- `test_provenance_cannot_be_relabelled.py` — flipping `proposer_provenance` breaks the
  record digest.
- `test_t3_is_severable.py` — **the slip fence.** No T1 or T2 module imports any T3
  module. This is what lets T3 slip alone (§3.3 of the directive) without dragging
  anything, and it is a structural assertion so it cannot rot.

**Gates.** Every stage report quotes `python -m scripts.gate --all` verbatim, per R049
§2 — the runner, never hand-typed commands.

## 6. Schema and migration numbers

**No enforcer migration number is claimed, and none is needed.** Draft state lives in
`studio.db`, which carries its own `SCHEMA_VERSION` (currently `2`) precisely so the
enforcer's numbered sequence stays the enforcer's history (R047 §2; `0019`+ released).

Studio schema **2 → 3**, forward-only, both columns nullable:

- `policy_candidates.state` — `draft` | `submitted` (T2's submit-for-ratification).
- `policy_candidates.derivation_record_digest` — the T3 link to the existing
  append-only `derivation_records` row.

Rows written at version 2 carry `NULL` and render an explicit marker, in the
`unchained`/`unattributed` shape this channel has used twice. `open_store` already
upgrades forward and already refuses a store from the future.
