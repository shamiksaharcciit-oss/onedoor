enforcement** — a `-00` enforcement point still denies correctly against this
release, because a PEP's behaviour is fixed by the verdict and never by the reason
string. Seven work items, in the order they had to land:

## 2. §implstatus — A4 and A4b move to met, and A4b's sentence is now testable

R021 asked that W6's tests make the disclosure sentence checkable. They do, one test
per clause, named for the clause: *"cannot express not_attempted or timeout"*,
*"both collapse to failed"*, *"settles before the outcome is examined"*,
*"permanently charges budget"*, *"releasing the reservation"*, *"as an audited
event"*. When `-02` is authored, `tests/guardrail/test_report_outcome.py` is that
section's evidence and can be cited as such — the IETF text and the implementation
now share a truth maintained by CI.

Two edge guards sit beside them, because the release is what makes them load-bearing:
a **timeout still charges** (releasing on doubt would let a caller free budget *by
timing out*), and a report arriving **after reclamation does not release twice**.

## 3. What a deployer has to do, stated in the CHANGELOG before anything else

Ordered by how likely each is to touch them, because a breaking release that does not
say plainly what to change is a breaking release twice:

1. `report_result(..., ok: bool)` → `report_result(..., outcome: Outcome)`, and
   `POST /v1/report` takes `"outcome"` instead of `"ok"`.
2. `cap_daily_rate` / `cap_eur_day` / `cap_eur_month` are gone — match `cap_rate` /
   `cap_value` and read the window from the `budget` object.
3. **The policy content-hash changes once even for unchanged rules**, because
   decimals now record canonically. `snapshot_schema` is what makes that diff
   attributable rather than alarming.
