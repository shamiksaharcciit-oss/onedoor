## 2. The `not_attempted` defect is three defects, and one of them is a budget bug

Core asked delivery to record a live conformance defect: onedoor's outcome vocabulary
admits only `executed|dry_run|proposed|denied|failed`, so a conformant PEP sending
`not_attempted` is mishandled. Verified — and the root cause is one level below the
vocabulary, which makes the consequences worse than a missing enum value.

**`report_result` has no outcome parameter at all.** It takes a boolean:

```python
def report_result(intent, *, conn, config=None, ok: bool,
                  payload, error, now) -> ActionResult:
    """... Must be called exactly once per PermittedIntent, whatever the
    enforcement outcome — success, failure, or timeout."""
```

§reportreq requires one of **four** outcomes. onedoor's report interface can express
**two**. The docstring names three and implements two. `not_attempted` and `timeout`
have nowhere to go; both collapse to `ok=False`.

Three distinct defects follow:

### 2a. Evidence correctness — the audit asserts something that did not happen
`ok=False` produces `Decision.FAILED` and publishes `action.failed`
(`decision.py:399,404`). So a `not_attempted` report — meaning *the PEP refused an
obligation and the action never ran* — is recorded as an action that **was attempted
and failed**. For a product whose audit is the deliverable, an evidence row that
asserts an attempt that never occurred is the most serious class of bug available.
`timeout` has the same collapse, and `timeout` is genuinely ambiguous (the action may
or may not have happened), so recording it as `failed` is an overclaim in the other
direction.

### 2b. Budget correctness — a never-attempted action permanently consumes budget
The settlement runs **unconditionally, before the outcome is examined**:

```python
with tx(conn):
    conn.execute("UPDATE cap_reservations SET status='settled' "
                 "WHERE intent_audit_id=? AND status='held'", ...)
```

So the reservation is spent whatever the PEP reports. A conformant `not_attempted` —
the case E9's `idempotency_key` obligation is *designed* to produce — **permanently
charges €/day and €/month budget for an action that never occurred.** Repeated across
a fleet of PEPs whose adapters cannot honour an obligation, a tenant's budget drains
against zero real-world effect, and the caps stop meaning what the policy says they mean.

This is not reachable today only because nothing emits obligations. **It becomes
reachable the moment `ND-038` ships**, which is precisely why core's dark-surface rule
(enforcement before emission) needs a third clause: *and the report path must handle
every outcome the spec admits before any obligation is attached.*

### 2c. The API shape, not just the vocabulary
Adding `not_attempted` to the `decision` enum does not fix this. The fix is an outcome
parameter on `report_result` replacing `ok: bool`, threaded through both packaged PEPs
and the `/v1/report` binding. That is a public API change to the in-process binding —
delivery's call, not wire-observable — but it is `M`, not the enum edit it looked like.

### The question for core

**What is the correct disposition of a held budget reservation for each outcome?**
`-00` §reportreq defines the outcome vocabulary; delivery could not find text binding
outcome to reservation disposition, and this is budget-accounting behaviour, so it is
core's.

Delivery's reading, offered as a starting point:

| Outcome | Reservation | Rationale |
|---|---|---|
| `success` | settle | the effect happened |
| `failure` | settle | attempted; cost may have been incurred; conservative |
| `timeout` | settle | genuinely unknown whether it happened — must assume it did |
| `not_attempted` | **release** | the action provably did not occur; charging for it is the bug in 2b |

The asymmetry is deliberate: settle-on-doubt, release only on the one outcome that is a
positive assertion of non-occurrence. Note the abuse surface is benign — a PEP falsely
claiming `not_attempted` frees only its own budget for an action it also didn't perform,
so it gains nothing; whereas the current always-settle behaviour lets an obligation the
PEP *correctly* refused drain the tenant's caps.

**Scope:** the fix lands in `0.4.0` alongside the vocabulary work, per core's
instruction to fold it in. Delivery is adding `ND-039` for the report-outcome rework and
has re-marked the A-series row. `0.3.6` is unaffected and proceeding.
