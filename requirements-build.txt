# sha256 (pip's own hash-checking mode: `pip install -r requirements-build.txt
# --require-hashes`). Not a floor, not a range -- a release built with any
# other version of any of these is not the release this repository signs off
# on. tools/build_release.py enforces this: it checks the running venv holds
# exactly these versions before it builds anything, and refuses otherwise.

# A plain `python -m build` (no `--no-isolation`) ignores this file entirely:
# it builds its own isolated environment from pyproject.toml's own
# build-system.requires, which stays unpinned on purpose (an sdist installer
# is never held to this repository's own release pins). This file, and the
# --no-isolation build tools/build_release.py runs, are what make a release
# build repeatable regardless of what setuptools PyPI happens to serve that
# day -- the exact gap that let setuptools 84.2.1 build a wheel this
# repository's own pin never authorized.
